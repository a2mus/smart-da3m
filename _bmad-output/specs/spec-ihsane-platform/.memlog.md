### OQ-Arch-2 RESOLVED
Content is shareable at the platform level: generated and validated knowledge atoms, remediation templates, tests/modules. This is the `is_shared` flag from AD-4. Personal data (student sessions, answers, paths, mastery profiles, alerts) is NOT shareable — strictly tenant-scoped. So:
- Shared content: owned by system org, `is_shared=True`, all tenants can read
- Private content: owned by an org, `is_shared=False`, only that org can read
- Personal data: always tenant-scoped, never shareable

### AD-4 amendment — Experts can supervise multiple schools
Experts are NOT bound to one organization. An expert can be assigned to or supervise multiple schools (organizations).
- Students and parents: one-to-many (belong to exactly one org)
- Experts: many-to-many (can belong to multiple orgs, via an association table)

This changes the data model: instead of a simple `organization_id` FK on User, we need an `OrganizationMember` association table with `user_id`, `organization_id`, and `role` (STUDENT/PARENT/EXPERT).

## Entry — Hybrid tenant model + platform pedagogue pool

### Decision: Hybrid org model (Option B)
Two modes coexist:
- **School mode**: an organization (school) onboarded its teachers and students. Parents linked through their children.
- **Family mode**: an independent parent self-registers, gets an auto-created "household" pseudo-org, creates child accounts, picks a curriculum level, uses the platform standalone — no school involved.

### Decision: Parents are many-to-many with orgs
A parent with children in different schools needs access to each child's data (scoped to their respective schools). Updated:
- Students: one org (their school) OR a household pseudo-org
- Parents: multiple orgs (one per child's school + their own household if independent)
- Experts: multiple orgs (schools they supervise + platform-level pool)

### Decision: Platform-level pedagogue pool for independent families
Independent families don't have their own expert. The platform has a pool of platform-level pedagogues who review remediation proposals for independent families. These experts belong to the system org and handle the validation queue for household-mode students.

### Data model implications
- `Organization` has a `type` field: `SCHOOL` or `HOUSEHOLD`
- `OrganizationMember` join table covers all cases (many-to-many for all roles)
- Platform pedagogues are experts in the system org with a flag `is_platform_pedagogue = True`
- The remediation PROPOSED queue routes: if student's org is SCHOOL → that school's experts; if HOUSEHOLD → platform pedagogue pool
